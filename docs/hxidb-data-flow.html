HXIDB data flow

What the plugin sends, what the server keeps of it, and where it shows up on the wiki. The diagrams explain the mechanism; the list at the bottom covers every variable.

From game to server

The path of a report

Never sent: player names, character IDs or any hash of one, raw party member IDs, player positions (only a chest's own position), or anything written to the player's disk except the status box position. Identity and party tags come from an oblivious PRF, so the server never sees what they were made from.

What the plugin reads

The plugin handles incoming packets only, and only these six ids with a size from 8 to 512 bytes. It never blocks or changes a packet, reads no chat, and reads no other packet. Each card shows what is read from the packet, what is kept in memory, what is worked out, and what is finally sent.

0x00AZone change
Reads
The zone id (offset 0x30) and the game server's unix time (offset 0x38).
Keeps in memory
The current zone, and a clock anchor: the server time plus half a second, paired with the PC's monotonic clock. When the zone changes, everything held for the old zone is dropped: entities, pending kills, defeat de-duplication, the chest resend list and the Thief actions.
Evaluates
The time must be a plausible unix time. Kill times are then taken as the anchor plus the time elapsed since, so every reporter agrees whatever their PC clock says.
Sends as
zone_id, event_ms, time_anchored and event_minute.
0x00EEntity update
Reads
Unique id (0x04), entity index (0x08), position (0x0C, 0x10, 0x14), the first four model bytes (0x30) and the 16-byte name (0x34).
Keeps in memory
Per entity in this zone: name, model, position and the time it was first seen. Entities with an index of 0x400 or more (players and pets) are never read.
Evaluates
Names starting Treasure_Casket, Treasure_Chest, Treasure_Coffer or Armoury_Crate mark a chest. A chest that moves more than 1.0 units is treated as a new spawn.
Sends as
For a defeated mob, source_name and model. For a chest, the name, the position rounded to 0.1 and the spawn minute. A mob's position is never sent.
0x028Action
Reads
The actor id (0x05), the number of targets (0x09, 10 bits) and, from bit 150, each target id and its action count. What the action was and how much it did is skipped.
Keeps in memory
For each targeted mob: the highest Thief level among party and alliance members that acted on it, counting a sub-job Thief at the sub-job level. When the actor is the player, its own Treasure Hunter trait and worn gear are read at that moment. Cleared when the mob dies, on a zone change, or after 15 minutes.
Evaluates
The actor is looked up in the roster, which holds job and level only. Only mobs count. An action by someone with no Thief level and no own TH is dropped.
Sends as
th_acted_level, th_acted_known, th_self_trait and th_self_gear.
0x029Battle message
Reads
The message id (0x18), the target id (0x08) and the value (0x0C).
Keeps in memory
Message 6 (defeated) opens a pending event for that target, de-duplicated so one kill is not recorded twice. Message 565 (gil obtained) within 3 seconds adds the gil, if it is between 1 and 1,000,000 and none is recorded yet. The pending event waits 3 seconds, then is queued.
Evaluates
At the defeat the plugin also counts the alliance members eligible for the gil split, builds the anonymous party tags and the alliance flag, and attaches the Thief facts it noted.
Sends as
defeated_by_party, source_id, gil, gil_party, gil_party_zone, party tags, party_in_alliance, client_event_id. Every other message id is ignored.
0x0D2Treasure pool item
Reads
The source mob id (0x08), the item id (0x10), the quantity (0x04) and the server tick (0x18).
Keeps in memory
Nothing beyond the pending event it joins.
Evaluates
Attached to the pending kill with the same source id, within 3 seconds. A quantity of 100 or more is read as 1. The lowest tick over the kill's items becomes the kill tick. Pool-clear packets (source 0 or item 0) are ignored.
Sends as
drops and kill_tick.
0x034Chest interaction
Reads
The chest id (0x04), the event number (0x2C) and four item ids (0x08, four bytes each).
Keeps in memory
Which chest presentations were already sent for this spawn, for 300 seconds.
Evaluates
Only chests already seen in packet 0x00E count. The event number minus 1000, modulo 3, gives 0 for an items chest, 1 for a temporary-items chest, and 2 for a locked chest, which is ignored. A list with any value above 0xFFFF is refused, an empty list sends nothing, and a repeat is sent only if it gained an item.
Sends as
drops with their slots, chest_kind, the position, spawn_minute.

Memory reads

Party roster
Reads
Per slot 0 to 17: active flag, zone, main job and level, sub job and level, server id, target index.
Used for
Job and level feed the Thief lookup and the roster. Zone decides who is "in the zone". The server id is compared and run through the oblivious PRF to make anonymous tags; it is never stored or sent.
Entity table
Reads
Spawn flags, render flags and position of each party member and of the mob.
Used for
Counts the alliance members within 50 yalms of the mob (the render flag shows who the client still updates). Only the counts are sent, never a position.
Equipment and inventory
Reads
The 16 equipped slots and the item id in each.
Used for
Item ids are looked up in a Treasure Hunter table to give the gear bonus. Only the two numbers, trait and gear, are sent.

Where it shows on the wiki

Raw counts and percentages are always shown together, with a small-sample warning instead of hiding anything. The wiki reads only the aggregate v_stat views, which carry no reporter rows.
